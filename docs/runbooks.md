# 🚑 Инженерные инструкции и устранение сбоев (Runbooks)

Данный документ содержит регламенты решения типовых проблем, возникших при развёртывании и эксплуатации изолированного инженерного контура.

---

## 1. Мониторинг: Дашборды Grafana показывают «No data» или «N/A»

### Симптом
При подключенном источнике Prometheus и статусе `health: up` на дашбордах Node Exporter (ID: 1860, 11074) панели остаются пустыми.

### Причина 1: Рассинхронизация системного времени (Hyper-V Time Drift)
В виртуализации Hyper-V гостевая ОС может отставать или использовать некорректный часовой пояс (например, EST вместо MSK). Prometheus сохраняет метрики с таймстемпом сервера, а браузер запрашивает временной диапазон `[now - 15m]`. Если часы расходятся даже на 5–10 минут, запросы возвращают пустоту.

**Диагностика:**
```bash
date
timedatectl status
```
Решение:
Установить корректный часовой пояс:


``` Bash
sudo timedatectl set-timezone Europe/Moscow
```
Активировать сетевую синхронизацию времени по NTP:

```Bash
sudo timedatectl set-ntp true
```
Проверить статус синхронизации: ```System clock synchronized: yes.```

Причина 2: Несоответствие job_name в запросах PromQL

Большинство готовых дашбордов из каталога Grafana фильтруют метрики по шаблону job="node-exporter". Если в prometheus.yml задача названа произвольно (например, debian-node), шаблоны переменных возвращают пустые списки.

Решение:
В ```prometheus/config/prometheus.yml``` использовать стандартные имена задач:

```Yaml
scrape_configs:
  - job_name: 'node-exporter'
    static_configs:
      - targets: ['node-exporter:9100']
      ```
После изменения перезапустить сборщик: ```docker restart prometheus.```


2. Менеджер паролей: Блокировка Web Crypto API в Vaultwarden

Симптом
При открытии Vaultwarden через HTTP интерфейс выдает ошибку ```Crypto API is not available``` либо блокирует кнопку регистрации и ввода мастер-пароля.

Причина
Современные браузеры (движки Chromium и Gecko) блокируют функции криптографического API ```(window.crypto.subtle)``` для небезопасных соединений. Полноценная работа с паролями разрешена исключительно по протоколу HTTPS (либо на ```localhost```).
Решение: Выпуск внутреннего ```Wildcard-сертификата```
Генерация самоподписанного локального сертификата с расширением SAN на хосте:

```Bash
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout ~/homelab/certs/homelab.key \
  -out ~/homelab/certs/homelab.crt \
  -subj "/CN=*.lab" \
  -addext "subjectAltName=DNS:*.lab,DNS:vault.lab,DNS:grafana.lab,DNS:dashy.lab"
```
Загрузка сертификата в Nginx Proxy Manager: SSL Certificates -> Add SSL Certificate -> Custom.
В настройках хоста ```vault.lab``` включить:
SSL Certificate: Выбрать добавленный локальный CA.
Force SSL: Включено (редирект с 80 на 443).
HTTP/2 Support: Включено.
Websockets Support: Включено (для мгновенной синхронизации хранилища).


3. Реверс-прокси: Домен не привязывается в Nginx Proxy Manager

Симптом
После сохранения хоста в NPM переход по адресу ```http://service.lab``` открывает стандартную страницу-заглушку NPM «Congratulations! You've successfully started...».

Причина
Особенность веб-интерфейса NPM: поле Domain Names требует явного создания тега. Если после ввода имени домена не нажать клавишу Enter, поле отправляется на бэкенд пустым, и правило проксирования не создается.

Решение
Открыть редактирование Proxy Host.
Ввести имя домена и обязательно нажать клавишу Enter на клавиатуре (вокруг домена должна появиться серая рамка/плашка).
Сохранить изменения.


4. Развёртывание: Обрыв heredoc при передаче конфигов через SSH
Симптом
При вставке больших блоков через конструкцию ```cat << 'EOF' > file.yml``` в сессии Windows Terminal / PowerShell передача обрывается на середине файла, вызывая ошибки синтаксиса в Bash.

Решение
Избегать вставки объемных YAML-манифестов через поток heredoc. Использовать прямой текстовый редактор nano file.yml либо передачу через ```SCP```:

```Powershell
scp .\docker-compose.yml user@<SERVER_IP>:~/homelab/docker-compose.yml
```
---

#### Сохраняем:
1. Нажмите ```**`Ctrl + O`**``` -> ```**`Enter`**``` (сохранить).
2. Нажмите ```**`Ctrl + X`**``` (выйти).
